IDEF - DESCRIPTION
    Defines a custom callable instruction.

IDEF - SYNTAX
    IDEF <instruction name> <[args]...>

IDEF - OPERANDS
    instruction name
        The name of the instruction to define. VINSTR will allow any character (if it does not conflict with X Notation), including spaces, however it is a convention to have no delimiter between words (if any), and all uppercase.
    [args]...
        Arguments for the instruction. Can be an infinitely-long set of names for use in the custom instruction. The way to use arguments is explained in EXAMPLES.

IDEF - POSSIBLE ERRORS
    BinaryError.InvalidSyntax
        If you do not provide at least an instruction name, this is raised.
        If you do not provide an IEND marker to end the definition of the instruction, this is raised.

IDEF - GOTCHAS
    1.
        All following lines, up to but not including IEND, is caught for use of the custom instruction. These lines behave like normal VINSTR code. No formatting should be used (i.e., {...} blocks or indentation).

IDEF - EXAMPLES
    1.
        - Defines a simple instruction.
        IDEF CUSTOMINSTR
        SETVAL 0 1
        - IEND marks the end of the instruction.
        IEND
        - Calls the custom instruction.
        ICALL CUSTOMINSTR
        - [1, 0, 0, ..., 0]
        DEBUGVMREGDUMP
        HALT
    2.
        - Defines an instruction with arguments.
        IDEF CUSTOMINSTR CUSTOMARG1 CUSTOMARG2
        - Use '$' to address an argument when defining custom instructions.
        SETVAL 0 $CUSTOMARG1
        SETVAL 1 $CUSTOMARG2
        IEND
        - Use "ARGUMENTNAME:VALUE" to give these arguments values.
        ICALL CUSTOMINSTR CUSTOMART1:6 CUSTOMARG2:20
        - [6, 20, 0, ..., 0]
        DEBUGVMREGDUMP
        HALT
    3.
        - Shows an instruction with spaces (this is not recommended).
        - Uses |...| syntax.
        IDEF |INSTR WITH SPACES|
        SETVAL 1 7
        IEND
        ICALL |INSTR WITH SPACES|
        - [0, 7, 0, ..., 0]
        DEBUGVMREGDUMP
        HALT
